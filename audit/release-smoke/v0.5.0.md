## What the write probes actually did

Two real, reversible writes against live records, each verified by a
fresh read rather than by the write's own echo, and each restored:

- **A custom field set by its label.** The probe finds a deal carrying a
  dropdown, then learns that dropdown's choices *from the refusal
  itself* — it sends a deliberately invalid label and parses the
  "it takes one of: …" list out of the error. That is the house rule
  under test: a refusal the caller cannot act on is a bug, and this one
  is machine-actionable. It then writes a different valid label, reads it
  back, restores the original, and reads that back too.
- **An activity completed and reopened**, confirmed both ways by a fresh
  read.

Before the real write, the guard was exercised: replacing a populated
custom field without `overwrite` is refused, and an unknown custom field
is refused naming `refresh_field_cache`.

## The two assertions this release exists for

```
PASS a set custom field is present to judge              47 values
PASS no set custom field is a list of option ids         0 numeric list(s)
```

A multi-select custom field is the one case where an unresolved value is
unambiguous — a list of bare numbers. Before this release every one of
those 47 values was a list of option ids.

## Negative controls

A gate that cannot fail is not evidence. Both were watched failing
during development, against this same live workspace:

- `FieldCache`'s label resolution stubbed to a passthrough: the live
  integration probe reports **93 failures**.
- `CustomOf` removed from one resource's `guardedWrite`: **3** end-to-end
  tool tests fail, and the failure mode is visible in the output — the
  diff sees nothing, so the write is skipped as a no-op and never sent.

## What this does not cover

A **Claude Desktop** pass, specifically, has still not been done — for
the second release running. The runbook accepts a stdio client, which is
what produced this, so it is a gap in coverage rather than in process.
It is recorded in `docs/architecture.md` under the v0.5.0 items as still
open, and it should be closed before a third release leans on the same
substitution.

The live integration suite (`make integration-writes`, `-race`) covers
the write path, the guards over real records and the reversible probes,
and was run separately and green against this tree.
