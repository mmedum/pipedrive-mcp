## Stdio smoke

The binary built from this branch at ca67263 was driven over stdio by a script, not through Claude Code: the server in the Claude Code session is the installed release, not this branch. `PIPEDRIVE_DRY_RUN=true` was set as well, so a write that lost its `dry_run` would still have rehearsed; the integration suite's guard tests above hold the per-call `dry_run` without that floor. Every call read or rehearsed; nothing was written. The script printed counts and shapes only.

- `initialize` answered with protocol 2025-06-18, and tools/list with 20 tools. Stdout carried nothing but JSON-RPC frames.
- `whoami` answered with the signed-in user, the workspace, the timezone and the locale.
- `list_pipelines` returned the workspace's three pipelines, all active, the test pipeline among them.
- `list_stages` returned fifteen stages across them, each naming a listed pipeline. Asked for the test pipeline, it returned five, all in it.
- `list_deals` filtered to the signed-in user's open deals returned none, with no cursor: the whole answer, not an empty first page. Filtered to the test pipeline, none. Filtered to open deals with a limit of five, five rows, all open, with a cursor for the next page.
- `search` for the first of those deals' own title, deals only, returned two hits with that deal among them, not truncated.
- `get_deal` on that hit returned the same id, with its custom fields under their workspace names and none keyed by a hash.
- A dry-run `manage_deal` create in the test pipeline sent nothing. The reply named what a real create would set: the title, the signed-in user as owner, a currency code, the test pipeline and its first stage, and status open. Its `url` was empty. An exact search for its title found nothing.
