## Claude Code smoke

The maintainer registered the build under test in Claude Code with
local scope, ran two prompts, and removed it again.

1. `whoami` and `list_pipelines` answered, naming the signed-in account
   and the workspace's pipelines. Asked what `manage_organization` says
   happens to linked people and deals on a delete, the model answered
   from the new description: only the organization is deleted, restore
   is only in Pipedrive's UI within 30 days, and a dry run comes first.
   It called no write.
2. `list_deals` on the test pipeline returned no deals, so the model ran
   a dry-run `manage_deal` create there. The reply was marked
   `dry_run: true` and nothing was sent.

The model reading the dry-run create noted three things, all present
before this release and left for a later one: the reply carries a `url`
to deal 0, which does not exist; it shows `stage_id`, `currency` and
`owner_id` as zero values rather than what Pipedrive would fill in; and
it lists `status` as changed although the caller did not pass it.
