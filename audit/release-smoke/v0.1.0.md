# Release smoke — v0.1.0

**Date:** 2026-04-27
**Binary:** v0.1.0-prep build (commit `f47ba35` from main, then re-built
against the merged release-prep tree). Reproducible-build verified
byte-identical (`8703710e4c93cac08af21df0d5ae6d87fed5800757b5f9e3ad98bab1b22f0174`).
**Workspace:** maintainer's sandbox; identifiers redacted as parsed
summaries (no customer data per the project's audit hygiene rule).

## Method

The MCP smoke covers the full 16-tool surface (15 default + the
destructive `delete_note`, gated by `PIPEDRIVE_ENABLE_DESTRUCTIVE`).
Exercised through two independent code paths:

1. **stdio direct** — bash driver pipes JSON-RPC frames into the
   just-built binary, parses the responses with `jq`, and prints
   anonymized summaries (counts, IDs, error classes).
2. **MCP via Claude Code session** — the same Claude Code session
   running this audit had its `pipedrive` MCP server reconfigured
   to point at the prep build (binary swapped, `/reload-plugins` +
   `/mcp` reconnected so the session re-registered the new tool
   surface). Tools called directly via `mcp__pipedrive__*`.

Both paths exercised against the same workspace and same record
IDs so any divergence would surface immediately.

## Observations

- **Both code paths returned bit-identical data** for every tool
  exercised in both columns. Custom-field name resolution, cursor
  presence, and structured-output shapes match.
- **Three error classes** (`[not_found]`, `[validation]`,
  bogus-pipeline-id `[not_found]`) all returned with the right
  `[class]` tag and a renderable message body.
- **Both write tools' dry-run rehearsals are non-destructive.** For
  `delete_note` specifically, post-verify via `get_note` confirmed
  the target note's `active_flag` stayed `true` — the upstream
  DELETE was suppressed as designed.
- **`refresh_field_cache` fans out across the three resource caches
  in parallel** and reports `errors=0` with per-resource counts
  (`deals=59`, `persons=43`, `organizations=38`).
- **Server logs are stdout-clean** (only stderr emits `slog`
  records); no MCP-frame contamination, matching CLAUDE.md hard rule
  #2.

## Conclusion

The v0.1.0 binary is verified across the full registered surface
and ready for tagging.
