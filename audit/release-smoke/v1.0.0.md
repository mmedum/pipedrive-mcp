## The upstream mirror was re-captured, and that is the interesting row

`internal/pipedrive/testdata/v2-response-fields.json` holds Pipedrive's
own v2 description as an oracle for this package's hand-written types.
The spec itself moved — SHA256 `8cf6d47d…` to `fc2ce0fe…` since the
2026-09-18 capture — and **not one field on the seven mirrored types
changed**: no field added, none removed, none retyped.

That is worth stating rather than silently updating a hash. The check
exists because this mirror has drifted before, and the last refresh
found three real defects. This one found none, which is only
informative because somebody looked.

## What this release's evals found, and did not

Nothing new. That is the finding, and it is a weaker one than v0.6.0's
— which caught `manage_deal reopen` having been broken against the real
API since it shipped.

**`refuse-the-overwrite` failing 3/3 is a measurement, not a defect,
and this release is the proof.** v0.6.0 recorded that the model reads
the guard's refusal — which names `overwrite` as the argument that
would permit the write, because a refusal the caller cannot act on is a
bug — and re-sends with it set. It also recorded that rewriting the
field description to say a refusal is NOT a retry signal changed
nothing.

This release made `overwrite` name the fields it may replace, so the
blanket is gone: a model has to be wrong about each field separately,
and the call records which ones it claimed. The task still fails 3/3,
with the model sending `overwrite: ["title"]` — the exact array the
refusal printed.

So the per-field permit did what it was for (the blanket is gone, and
the claim is now specific and recorded) and did not do what it could
never do. Anything a refusal says, a model can echo back. Nothing
in-band prevents this, and the next person to look at this number
should treat it as instrumentation rather than a bug to close.

## Claude Desktop smoke: not done

Open across **five** releases now — v0.4.0, v0.5.0, v0.6.0 and this one
(v0.1.0 predates the requirement). The maintainer was asked before
tagging and chose to ship without it again.

What the automation does reach: `make smoke` against the built binary,
the live integration suite over the server that binary builds, and
three model-driven eval runs against a real workspace. What none of
them reach is the `.mcpb` bundle path — the generated launcher, and
keyring access from a GUI-launched process.

That untested surface is unchanged in size since v0.5.0. What has
changed is the promise over it: this is the release that makes the tool
surface stable, and the bundle is how most people will install it.
