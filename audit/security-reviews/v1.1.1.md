## What was checked

- **Writes stay on records the test created.** Every create and delete in the new test targets an id `newScratch` created, or the extra note the test makes on that scratch parent. `newScratch` still takes its pipeline from `requireOwnPipeline`, which skips without `PIPEDRIVE_TEST_PIPELINE_ID`, and still names records with the `mcp-test` prefix. No id taken from a listing is written to.
- **Workspace-wide reads.** `list_persons` and `list_organizations` read the newest 100 records, which can include real ones; rows are compared by id and never logged.
- **Teardown.** The deleted parent's id is zeroed and `dropOnCleanup` skips a zero id, so nothing is deleted twice and nothing the test did not create is deleted. No caller assigns a scratch field, so the pointer cannot redirect a teardown.
- **Secrets and customer data.** No tokens, company domain, real ids, names or addresses; the only address is `probe@example.invalid` (RFC 2606).
- **Tool descriptions.** The new text states verified behavior only, keeps "rehearse with dry_run first", and tells the model nothing unsafe. Annotations and handlers are unchanged.
