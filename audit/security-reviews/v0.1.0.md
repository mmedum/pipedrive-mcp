**Scope:** cumulative diff from the Phase 0 merge (`5024419`) to the
v0.1.0 release commit on `v0.1.0-prep` (HEAD before the rename PR).
**Reviewer:** /security-review skill (general-purpose subagent).

## Result

**No high-confidence security findings.**

## Coverage

The reviewer examined every file in the cumulative diff (47 commits,
8472+/353- across 64 files) for the security categories listed in the
skill prompt:

- URL path construction across every Phase 1 resource client
  (`internal/pipedrive/{deals,persons,organizations,activities,notes,stages,dealfields,pipelines,search}.go`).
  Every dynamic path component is either a fixed string literal or an
  `int64` ID formatted via `strconv.FormatInt`. No LLM-controlled string
  is ever interpolated into a path. `LeadID` (a UUID string) is only
  passed as a query value via `url.Values.Set` (proper percent-encoding)
  or as a JSON body field via `json.Marshal` (proper escaping).
- JSON-injection in `create_note` (`internal/pipedrive/notes.go`,
  `internal/tools/notes.go`). Body is built from a typed struct and
  marshalled with `encoding/json`. No string concatenation. `Content`
  and `LeadID` cannot break out of the JSON shape.
- Auth/token handling (`internal/pipedrive/client.go:newRequest`).
  Every request unconditionally sets `x-api-token` from `c.token`. No
  code path skips it or substitutes a different token. The probe
  (`probe.go`) discards its response, so the LLM never sees probe data.
  The token is never logged — the request log records URL + method +
  status only.
- Domain handling (`internal/config/config.go:ValidateDomain`, regex
  `^[a-z0-9][a-z0-9-]*[a-z0-9]$|^[a-z0-9]$`). Every entry point
  (`Load`, `LoadFor`, `cmdLogin`, `cmdLogout`, `resolveDomain`) routes
  through `ValidateDomain` before the value reaches `BaseURL` /
  `WebURL` or the keyring `account`. The userconfig fallback is also
  validated.
- Userconfig file handling (`internal/userconfig/userconfig.go`). Path
  comes from `os.UserConfigDir` (trusted env), atomic write-then-rename
  with 0600 file / 0700 dir perms, no traversal vector.
- TLS. Standard `http.Client` with no `InsecureSkipVerify`; cert
  validation intact.
- Command injection. No `os/exec`, no shell calls anywhere in the diff.
- Cursor decoding (`internal/tools/notes.go:decodeNotesCursor`).
  base64url + prefix check + `strconv.Atoi` with negativity guard.
  Failure returns a `[validation]` error.
- Error messages (`internal/pipedrive/errors.go`,
  `internal/tools/errors.go`). Raw response body is not retained on
  `APIError`; only the upstream `Message` is surfaced — consistent
  with the Phase 0 design.
- `AddTool` panic on schema-infer failure (`internal/tools/addtool.go`).
  Only fires on package init; `In`/`Out` types are author-controlled,
  not LLM-controlled.
- Cache warm goroutine (`internal/server/server.go`). Bounded by parent
  ctx + 30s timeout; no unbounded fan-out.

## Acceptance

The release proceeds without security findings.
