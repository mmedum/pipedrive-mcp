# Security review — v1.1.2

**Date:** 2026-10-01
**Range:** `v1.1.1..HEAD` (019ab7d, 85947b2, ef85c4a, cad99b3, bba83c0, 3f905bc, merges ce377fe and 451e445; then fe446d0 and f4de7c2, which fix what this review found)

## Findings

1. **Low, fixed in fe446d0.** Test values could belong to real people or companies. `scripts/gates/leaks_test.go` used a `.dk` freight domain, a company-shaped Pipedrive subdomain, a Danish-format mobile number and a New York number as reject cases. They were split by concatenation, so the gate could not see them, but if any were assigned, a third party's details sat in a public repository. The phone cases now use the ranges set aside for drama (Ofcom's London 020 7946 0xxx block and ACMA's 0491 570 xxx block), and the domain and subdomain use an invented string.
2. **Low, dev gate, fixed in fe446d0.** The phone rule missed common forms: parentheses (`+1 (646) …`) and a `00` prefix. Its fiction allow-list was not anchored, so a longer number that contained `555 01xx` passed. The rule now reads both forms, anchors the fiction range at the number's end, and needs nine digits, so a sum, a version or a diff count is not a number. National numbers with neither prefix are still not caught, and the rule's comment says so. Each new part was broken in turn and its test failed.
3. **Not a security issue, fixed in f4de7c2.** The first `WhoAmI` result was memoized for the life of the process, errors included. A dry-run create can now be the first caller, so a canceled call made every later `whoami` fail, and every dry-run preview show no owner, until restart. A call whose own context ended is no longer memoized. The test fails on the old code.

## What was checked

- **Writes are not repeated.** `shouldRetryNetwork` retries a non-GET only on a `*net.OpError` with `Op=="dial"`. A context error is never retried. A 429 means Pipedrive did not process the request, and 5xx is retried for GET only. Checked against the Go 1.27 standard library:
  - `CheckRedirect` returns `ErrUseLastResponse`, so no redirect is followed.
  - A dial error comes from `getConn`, before any byte is written.
  - Through a proxy, a failed dial is reported as `proxyconnect`, which is not retried.
  - `Transport.roundTrip` resends a POST only after `nothingWrittenError` or `NoCachedConn`.
  - HTTP/2 `canRetryError` covers only REFUSED_STREAM, GOAWAY and unusable connections, where the server did not process the stream.
  - A client timeout is `DeadlineExceeded` and is not retried, and a failed write carries the "may have been applied" hint.
- **Logs and errors.**
  - `*url.Error` is unwrapped, and the warn line, the debug line, the wrapped error and `classify` all use `pathOf`.
  - Every call site builds its path from fixed strings and `strconv.FormatInt`. Search terms, names and filters travel only in `buildPath`'s query, which is stripped.
  - The token is only in the `x-api-token` header.
  - What an error can still name is the workspace host, through a dial, DNS or TLS error, and the startup log already names it.
- **Dry-run create.** `fillOwner` and `fillDealDefaults` make only GETs: `/users/me` (v1, memoized) and `/stages?pipeline_id=` with an integer id. All four create actions still honor the `PIPEDRIVE_DRY_RUN` floor. The preview adds only the owner id, the default currency and the stage id, which `whoami` and `list_stages` already expose. `WebURL` returns `""` for an id of 0 or less.
- **New live test (`defaults_test.go`).** Records carry the `mcp-test` prefix, the deal goes in the suite's own pipeline, and `dropOnCleanup` deletes what the test created. No id taken from a listing is written to.
- **Fixtures.** The fixtures use invented values only: `Robin Sample`, `Acme`, `Example Transit Co`, `Freedonia`, `+1 555 0100/0101`, `+1-202-555-0142`, and addresses at `example.com` or `example.invalid`. `go run ./scripts/gates leaks` passes. The real values these replaced were also removed from the repository's whole history on 2026-10-01, every tag included. A fresh clone holds none of them.
- **Docs.** `docs/security.md` and `CHANGELOG.md` describe the behavior above accurately.
