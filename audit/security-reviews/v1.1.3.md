## What was checked

- **The toolchain.** `go.mod` moves from `go 1.26.0` with `toolchain go1.26.6` to `go 1.27.2`, and `release.yml` and `ci.yml` build with Go 1.27.2. govulncheck v1.8.0 on `v1.1.2` under Go 1.26.6 reports nine standard-library advisories the code reaches; under Go 1.27.2 it reports none. Its two dependency advisories are in code this server never calls, before and after.
- **Tool pins.** govulncheck moves from v1.1.4 to v1.8.0 and golangci-lint from v2.13.2 to v2.14.0, in the Makefile and in CI, both pinned by exact version as before.
- **`assign-issues.yml` (new).** It runs on `issues: opened, reopened`, with `permissions: {}` at the top and `issues: write` on its one job, so it can do nothing but edit issues. It uses the `gh` on the runner, so there is no third-party action to pin. The issue number, the repository and the owner reach the script through `env`, never spliced into it, so an issue title or body cannot inject a command: the script reads none of them.
- **`CODEOWNERS` (new).** It requests the owner's review on every pull request. It grants nothing.
- **The tool surface.** `--dump-schemas` from v1.1.2 and from the release commit are byte-for-byte identical: 20 tools, no name, field, enum or description changed.
