# Security review — v1.0.0

**Range:** `v0.6.0..HEAD` (35 files, ~1645 insertions)
**Date:** 2026-09-24
**Result:** no HIGH or MEDIUM findings.

Run with `/security-review` over the cumulative diff since the previous
tag, per `docs/release.md`. The review covered every non-test Go change
in the range plus surrounding context in `internal/pipedrive/client.go`,
`internal/pipedrive/errors.go`, `internal/tools/errors.go`,
`internal/tools/pagination.go`, `internal/pipedrive/types.go`,
`docs/security.md` and `CLAUDE.md`.

## Findings

None at HIGH or MEDIUM severity.

## What was checked and cleared

**`internal/pipedrive/liveness.go`** — the new HTTP path built from a
caller-supplied item type plus caller-supplied ids. No injection or
traversal surface: the path comes from a closed map and an unknown type
is refused with `ErrValidation`, so nothing caller-controlled reaches
the path. Ids are `int64` rendered numerically and set through
`url.Values`. Chunking at the documented 100-id cap is the right
direction — truncation would be read as "deleted" and would drop live
records.

**`internal/tools/search.go`** — the new filter that drops results. The
key used to bucket ids and the key used to filter are the same
expression, so a hit cannot be checked under one type and dropped under
another. A hit with a missing type, or a type with no liveness
collection, is never checked and always kept. A failed liveness call
fails the whole search rather than returning an unfiltered page. No
case was found in which a live record is dropped.

**No token leak.** The token travels in the `x-api-token` header, never
in a URL or query string; redirects are refused; `APIError` carries only
class, status, upstream message and path. The new error wrapper uses
`%w`, so `errors.Is` classification still works and no new field is
exposed.

**No stdout contamination.** The only `fmt.Print*` added is in
`scripts/evals/main.go`, which is `package main` and already printed.
Nothing under `internal/` gained a print or an `os.Stdout` reference.

**The `overwrite` change does not weaken the guard.** The permitted set
is derived from the same diff that produces the `changed` report, so
guard and report cannot drift. Matching is exact-string, so a mismatch
fails closed. `OverwriteAll` is set only from the transition tables,
never from caller input. Because the schema type changed, an old-style
`overwrite: true` now fails schema validation rather than being
coerced — fail-closed.

**The `PIPEDRIVE_DRY_RUN` floor is intact.** The new `Validate()` calls
were placed before the dry-run branch, so a rehearsal is refused on the
same input a real write would be, and no path was added that builds
`RegisterOptions` outside `internal/app`.

**No customer data introduced.** The invented records in the range are
`Acme Industries (eval …)`, `mcp-test <timestamp>`,
`probe@example.invalid` (RFC 2606) and
`pipedrive-mcp-probe@example.com`.

**No quality gate touched.** No changes to `.golangci.yml`, `Makefile`,
`.github/` or `scripts/gates` in the range. The one `t.Skip` removed
was replaced with `t.Fatal`.

## Two non-vulnerability findings, reported rather than filed

**A tool's guidance never reached the LLM.** `llmMessage` returned
`apiErr.Message` alone and discarded the wrapper, so the
search-liveness failure guidance was dead text and its comment said
something untrue. Correctness, not a vulnerability. **Fixed before the
tag** — PR #93.

**Eval drift detection for edits is now non-fatal.** `report()` in
`scripts/evals/main.go` fails the run only for records the run
*created*; a non-fixture record being *edited* is printed rather than
failed. The rationale — a colleague editing a record on a shared
workspace is not the model's drift — is documented and reasonable, but
this is the same detection class that would have caught the incident
this release exists to fix: a model mutating, not creating, a real
record.

**Not changed, and deliberately.** The alarm is a dev-harness control,
not a shipped one, and the guard that actually prevents the incident is
elsewhere: no probe or fixture touches a record it did not create, and
deals live in `PIPEDRIVE_TEST_PIPELINE_ID` with no default. Making the
edit alarm fatal again on a shared real workspace would fail runs for
other people's ordinary work, which is how an alarm gets switched off
for good. Worth revisiting if this ever runs against a workspace
nobody else uses.
