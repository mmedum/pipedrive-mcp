## Verdict

**Clean. No HIGH or MEDIUM finding reached the reporting bar.**

Every write path in the range — create, update, the six `manage_deal`
actions including the new `archive`/`unarchive`, and the new
custom-field path on all three resources — was traced end to end against
the `overwrite` refusal, the `expect_version` check and the
`PIPEDRIVE_DRY_RUN` floor. Each guard holds on every path.

The finding from the per-PR passes — a built-in field named by its
**key** (`"title"`) slipping past the custom-field check, so the guard
measured an always-empty value and never demanded `overwrite` — is fixed
and still fixed, with regression coverage for both spellings
(`fieldcache_test.go`, "built-in field by name" and "built-in field by
key").

## Checked and dismissed

**The write spine.** `guardedWrite.run` fixes the order once for every
resource: fetch → `expect_version` → build spec → predict → diff →
`requireOverwrite` → dry-run gate → `Put`. There is no second copy.
`manage_note`'s delete is the one mutation that does not enter through
it; it runs the same `expect_version` check and honours `DryRun`, and
the v1 soft delete is reversible by read, so per the contract it
correctly takes no permitting argument.

**No field is written that the diff cannot see.** Each update-request
struct was held against its field table by hand — deal, person,
organization, activity, note — and all five are complete. `is_archived`
was added to `dealBaseFields` in the same commit that made it writable,
so the new field did not arrive untabled. A writable-but-untabled field
is written without being guarded *or* reported, which makes this the
failure mode that would matter most.

**The overwrite guard fails closed on every degenerate input
constructed.** `populatedFields` unions across every spec entry whose
name is in `changed`, so duplicate names — a workspace custom field
named exactly `title`, or two custom fields sharing a name — can only
add refusals, never remove one. An empty `changed` short-circuits before
`Put`, so an invisible change means no write rather than an unguarded
one.

**Custom-field emptiness is conservative.** Only `nil` and `""` render
unpopulated. A stored `false`, `0`, empty multi-select or structured
value all demand `overwrite`. Multi-selects sort before joining, so a
reorder is not a change, and each element is quoted so two distinct sets
cannot render alike.

**Transitions self-authorising `overwrite` is contract-conformant and
correctly scoped.** Each transition builds a request containing only the
field it names — `archive` is `{IsArchived: true}` and nothing else —
and returns a nil custom-field map, so a caller passing `title` or
`custom_fields` alongside `mark_won` gets neither written nor waved
through. The self-authorisation cannot be widened by the caller.

**The `PIPEDRIVE_DRY_RUN` floor is intact on every write tool**,
including the create paths. `server.New` remains the only place a
serving process builds `tools.RegisterOptions`; `NewForSchemaDump` has
no client and no handler, so it has no floor to drop.

**The archived-deal guard** lives inside `guardedWrite.Get`, the first
thing `run` calls. Attempts to turn it into a bypass, all closed:
smuggling other fields through `unarchive` (the request carries only
`is_archived`); skipping it via create (`CreateDealRequest` has no
`is_archived`); ordering it around `expect_version` (both refuse,
neither skips the other); using it to hide a record (`archive` is
reversible and `list_deals` exposes the archived collection, so per the
contract `force` is correctly absent).

**The vendored-schema SHA256 pins.** Both hashes verified against the
committed files. The control is bounded and the code says so in its own
words: it proves the bytes are the ones somebody reviewed, not that they
still match what the URL serves. Against commit access it buys nothing;
against a vendored file edited or refreshed without review it is a real
tripwire, paired with a URL pin so version, ref and bytes move together.
Critically, **nothing security-relevant now rests on it**: the
`fileSha256` published to the MCP registry — the value clients verify a
download against — comes from the release's own `SHA256SUMS`, not from
anything the schema pin covers. Validation resolves only local `$ref`
fragments, so it performs no network fetch.

**Aliasing and cross-call leakage.** `withCustomFields` builds a fresh
slice and never appends into the package-level base tables; the empty
fast path returns `base`, which is only read. The per-entry closure
captures `key` per iteration (`go.mod` declares `go 1.26.0`; under a
pre-1.22 language version every entry would have read the last key, a
silent and total failure). `mergeCustomFields` copies, so the prediction
never writes through to the record the diff still compares against.
`FieldCache.Resolve` allocates a fresh map and never mutates its input.

**Stdout discipline.** No `fmt.Print*` or `os.Stdout` outside `main`.
`internal/tools` contains zero logger references, so no record content,
custom-field value, note body or dropdown label reaches a log sink. The
client logs URL, method, status, attempt and duration only — no bodies —
and auth travels in a header, not the URL.

**Arbitrary key injection into a write body is not reachable.** Both
branches of `writableField` yield keys drawn from Pipedrive's own field
codes; a caller cannot place a key of their choosing into
`custom_fields`.

**Case-folded dropdown labels** (below the bar, noted): the write side
lowercases labels, so two options differing only in case would collide
and the last loaded would win. It needs a workspace containing
case-colliding labels, the wrong value is still a valid option on the
same field, and the write remains subject to the `overwrite` refusal.

## Non-security observations, and what was done about them

All three were confirmed and fixed before the tag rather than filed:

1. **`internal/server/server.go` — the MCP `instructions` still said
   custom fields were "not yet writable"**, which this release makes
   false on three resources. That string is the first thing a connecting
   client reads. Fixed, along with the transition list, which omitted
   `archive` and `unarchive`.
2. **`docs/security.md` promised that dry-run invocations are logged at
   `info` so an operator could audit them.** No tool handler logs
   anything, so no such record has ever been written. The sentence now
   says so and points at the roadmap entry.

## Method

Read the cumulative diff in full, then the surrounding files rather than
the hunks alone for every write path, the guard machinery, the field
cache, the gate binaries and the server wiring. Traced each of the five
`manage_` tools from handler entry to HTTP request. Held each
update-request struct against its field table by hand. Constructed and
refuted specific bypass scenarios for the overwrite refusal, the
archived-deal guard and the dry-run floor. Verified both vendored-schema
hashes against the files on disk, and the prior finding's fix and its
regression tests. No files were written and nothing was executed against
a live workspace.
